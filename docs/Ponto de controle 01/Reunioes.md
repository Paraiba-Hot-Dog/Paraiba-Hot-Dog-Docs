# Reuniões da equipe

> Resumo das reuniões do grupo, contendo decisões principais, datas e alinhamentos realizados ao longo do projeto.

> Os encontros com o cliente são conduzidos por Daniel Ferreira. O cliente possui um perfil de envolvimento sob demanda, com alinhamentos apenas quando necessário

> Internamente, a equipe se organiza principalmente via WhatsApp, pela agilidade na comunicação.

---

## R01 — Definição Tecnológica

| Data | 16/03/2026 |
|------|------------|
| Resumo | Alinhamento inicial do projeto, com definição das tecnologias |
| Decisões | Foi decidido que o backend será desenvolvido em Python com FastAPI, o frontend em React, os protótipos serão feitos no Figma, a infraestrutura utilizará Docker e o backlog será gerenciado no Jira |
| Próximos passos | Foi definido que serão criados o backlog inicial, os primeiros protótipos no Figma e a configuração do ambiente de desenvolvimento |

---

## R02 — Criação das US's

| Data | 23/03/2026 |
|------|------------|
| Resumo | Organização das Histórias de Usuário (US) e alinhamento do escopo com base nas recomendações do professor |
| Decisões | Foi decidido adotar a abordagem mobile first, permitir a anotação de pedidos com atualização automática dos gráficos, criar uma página dedicada ao BI, desenvolver um protótipo de alta qualidade no Figma e limitar o projeto a até 15 US com no máximo 5 requisitos por cada uma |
| Próximos passos | Foi definido que o grupo iniciará a estruturação das US priorizando funcionalidades essenciais, relacionará os requisitos por US para facilitar o planejamento do backlog e selecionará o máximo possível de requisitos até a próxima segunda-feira |

---

## R03 — Divisão de Responsabilidade

| Data | 06/04/2026 |
|------|------------|
| Resumo | Alinhamento das responsabilidades do grupo, com foco na divisão entre prototipação e desenvolvimento inicial da arquitetura e backend, além de ajustes na forma de organização do projeto |
| Decisões | Foi decidido dividir o grupo entre responsáveis pelo protótipo e pela arquitetura e infraestrutura, incluindo o início do backend com definição de controladores para adiantar as atividades, adotar protótipos de média fidelidade para maior agilidade, distribuir telas específicas para cada integrante desenvolver e organizar o projeto com base nas entregas definidas pelo professor, deixando de utilizar o Jira conforme planejado anteriormente |
| Próximos passos | Foi definido que os integrantes responsáveis pelo protótipo iniciarão a construção das telas no Figma, enquanto os demais darão início à estruturação do backend e da arquitetura com Docker, além de manter alinhamentos contínuos pelo WhatsApp e consolidar decisões em reuniões apenas quando necessário |
